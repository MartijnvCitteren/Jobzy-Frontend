# Team Learnings — Jobzy Frontend

Findings from retros after each epic/task wraps up. Read before starting work — patterns here compound over time.

## 2026-09-25 — Vacancy-creation fine-tuning pass (T034–T043)

**What worked**
- Test-first development kept logic bugs minimal; 138→173→179 test count shows good coverage growth.
- One screenshot per changed screen confirmed the PO-reported layout bugs (grid overflow, collapsing `<hr />`, select sizing) were actually fixed, and let the lead spot the remaining copy/empty-state/grouping issues before review rather than after another PO round.
- Two-round review (REQUEST_CHANGES → APPROVE) worked well for this level of polish — 5 findings all fixable without scope creep.
- Feature-local merge pattern (§11.2: each form merges omitted fields against its own response) is elegant and avoids page-state explosion.

**What wasted tokens or time**
- **Wording locked in by developer's own tests** (3 files with `"5 dagen per week"`→`"5 vakantiedagen per week"`). Review caught it, but this is a Dutch-language copy issue that should have been read before the tests shipped, not discovered during review. Token waste: 1 round-trip to fix test strings + assertions.
- **JSDOM-based tests for grid layout are fundamentally fake.** `repeat(auto-fit, minmax(...))` reflow can't be asserted in JSDOM; the plan's own §10.6 noted this ("if the test setup can't genuinely assert grid reflow… downgrade to a manual verification step"), but T032's "audit instead of browser check" and T034-T042 specs didn't explicitly call out "take a screenshot at 800px/1024px to verify no overflow" as part of the developer's done criteria. Result: grid overflow + textarea drag bugs only found when the PO opened a browser.
- **Empty read-only sections rendering blank.** This is a presentational spec detail (placeholder text for "Nog niet ingevuld") that tests often skip — it's not a logic bug, so "exists, renders" tests pass, but "looks empty" is a UX problem. Should have been in the design handoff or design-notes.md as explicit spec, not inferred at review time.
- **Playwright/Chromium version mismatch workaround lived outside the repo** (symlinked binaries in `/opt/pw-browsers`). This is an environment-provisioning gap, not a developer mistake, but it's a signal that the sandbox's browser cache drifted from the lockfile's Playwright version — should have been fixed at the environment level, not worked around.

**What to change**
- **Real-browser visual check as part of done criteria for screen changes.** Add to the developer's definition of done: "Resize to 800px and 1024px widths, verify no horizontal scroll, no grid overflow, no flex wrapping into a second row." JSDOM can't catch this; a screenshot at each width takes <2min and catches layout bugs that 173 tests miss. Make this explicit in task specs (especially `[T0XX] Rework: …` tasks touching CSS/layout).
- **Dutch-language copy review before APPROVE.** Strings like `formatHolidayDays` output ("X vakantiedagen per week"), error messages, section placeholders — add a pass-through for a Dutch speaker (PO or lead) *during* the review, not after sign-off. This is especially important for user-visible copy generated by formatters (not hardcoded in JSX, so easy to miss).
- **Explicit spec for empty-section placeholders.** Decide once: do read-only sections render a placeholder ("Nog niet ingevuld") when empty, or do they render as visually-empty paragraphs? If a placeholder, call it out in the design handoff or the plan — don't leave it to infer. This one was only 5 finding lines of code, but it's a pattern: "rendering something when the data is empty" should be explicitly specified, not assumed.
- **Merge PATCH responses defensively as a pattern.** This pass's §11.2 solution (feature-local merge in each form's `save()`) worked well and didn't require a new store. If a third form develops the same "response may omit what I just submitted" shape, replicate this pattern — don't escalate to page-level state machinery unless the pattern repeats 3+ times across different pages/features.
- **Environment: lock Playwright version to the sandbox's preinstalled browser revision.** The mismatch was pre-existing (lockfile expected 1243, `/opt/pw-browsers` had 1194), but nobody caught it until an agent needed to run e2e tests. A quick smoke check at session start (compare the Chromium revision `npx playwright --version`'s release expects against what's in `/opt/pw-browsers`) would surface this immediately.
